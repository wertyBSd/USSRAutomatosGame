# USSRAutomatosGame — дизайн-документ

Сборник-антология из пяти аркадных автоматов эпохи СССР, оформленный как виртуальный зал игровых автоматов. Движок — Godot 4.7 (Forward+, D3D12).

---

## 1. Общая идея

Игрок попадает в трёхмерный зал аттракционов. В зале стоят пять кабинетов. Подойдя к кабинету и нажав «играть», игрок запускает мини-игру. Каждая мини-игра — самостоятельная аркада, но все они живут внутри одного каркаса: экран 4:3, низкое внутреннее разрешение, CRT-шейдер, семисегментный счёт, общая палитра и звук.

**Ключевой принцип:** пять игр — это пять разных механик, а не пять вариантов одной. Реакция, прицеливание, тактика, точность, физика.

**Правовая рамка.** Советские автоматы были оптико-механическими, готового ПО в них не существовало. Мы реализуем механики самостоятельно. Все арт-ассеты, шрифты и звуки — собственные или CC0. Никаких чужих записей и фотографий из музеев.

## 2. Пять автоматов

| ID | Название | Жанр | Ядро механики |
|---|---|---|---|
| `naval_battle` | Морской бой | Прицеливание с упреждением | Торпеда идёт с задержкой, корабли движутся с разной скоростью |
| `highway` | Магистраль | Реакция | Дорога уезжает вниз, объезд встречных, обгон попутных |
| `tankodrome` | Танкодром | Тактика | Вид сверху, башня отдельно от корпуса, волны врагов |
| `sniper` | Снайпер | Точность | Мишени и «гражданские», лимит времени и патронов |
| `gorodki` | Городки | Физика | Выбивание фигур битой, ограниченное число бросков |

### 2.1 Морской бой (`naval_battle`)

Вид из перископа на море. По горизонтали движутся корабли трёх классов.

- **Малый катер** — быстрый, мало очков, близко.
- **Эсминец** — средняя скорость, средние очки, средняя дистанция.
- **Линкор** — медленный, много очков, далеко и мал на экране.

Игрок наводит прицел (крест) и пускает торпеду. Торпеда идёт к цели **с задержкой**, поэтому нужно брать упреждение по курсу корабля. Промах — потеря торпеды.

- Торпед в боекомплекте: 20.
- Попадание по катеру: 100, эсминец: 250, линкор: 500.
- Множитель за серию попаданий подряд (до x4).
- Конец игры: торпеды кончились.

Управление: мышь/стрелки — прицел, Space/ЛКМ — пуск.

### 2.2 Магистраль (`highway`)

Псевдо-3D дорога уезжает вниз (режим «гонки»). Скорость растёт со временем.

- **Встречная полоса** — машины едут навстречу, столкновение смертельно.
- **Попутная полоса** — машины едут медленнее, обгон даёт очки.
- Обочина замедляет, но безопасна.
- Очки = пройденная дистанция, бонус за обгоны вплотную.

- Стартовая скорость: 80 км/ч, рост +2 км/ч каждые 1000 очков.
- Три жизни.

Управление: ←/→ или A/D — руль, ↑/↓ или W/S — газ/тормоз.

### 2.3 Танкодром (`tankodrome`)

Вид сверху. Поле с препятствиями (бетонные блоки, деревья).

- Свой танк: корпус поворачивается клавишами, башня наводится отдельно.
- Враги появляются волнами по 3–6 единиц, стреляют в ответ.
- Типы врагов: лёгкий (быстрый, слабый), тяжёлый (медленный, бронированный), стационарная пушка.
- Броня игрока: 3 попадания.

- Очки: лёгкий 150, тяжёлый 400, пушка 250.
- Волна засчитывается при уничтожении всех врагов; между волнами короткая пауза.

Управление: WASD — корпус, мышь — башня и выстрел, Space — выстрел.

### 2.4 Снайпер (`sniper`)

Тир. Мишени появляются в случайных точках и движутся с разной скоростью.

- **Круглые мишени** — дают очки.
- **Красные (гражданские)** — штраф и потеря времени. Попадать нельзя.
- Лимит времени: 60 секунд. Патронов: 30.
- Попадание в мишень даёт 120, в «яблочко» (центр) — 250.
- За промах — штраф 0, но патрон тратится.

Управление: мышь — прицел, ЛКМ/Space — выстрел.

### 2.5 Городки (`gorodki`)

Русская народная игра. Из фигур-«рюх» выбивается бита.

- Фигура собирается из деревянных чурок (цилиндров) в определённой раскладке.
- Игрок целится и бросает биту. Физика: чурки разлетаются, выбитые за линию — очки.
- Ограниченное число бросков на фигуру (3).
- Фигуры идут от простых («Пушка») к сложным («Звезда»).

- Очки: за каждую выбитую чурку 50, за полностью разбитую фигуру бонус 300.
- Конец: броски кончились или все фигуры разбиты.

Управление: мышь — прицел и сила, ЛКМ — бросок.

## 3. Архитектура

```
┌───────────────────────────────────────────────────────────┐
│ Autoload: GameManager · ScoreStore · Settings · Loc       │
├───────────────────────────────────────────────────────────┤
│ Framework: ArcadeScreen (SubViewport+CRT) · GameBase      │
│            ScoreDisplay · Palette · Sfx                   │
├───────────────────────────────────────────────────────────┤
│ Hub (3D): Hall · Cabinet · PlayerController               │
├───────────────────────────────────────────────────────────┤
│ Machines: naval_battle · highway · tankodrome · sniper ·  │
│           gorodki                                         │
└───────────────────────────────────────────────────────────┘
```

### 3.1 Автозагрузки

- **GameManager** — реестр автоматов, запуск/остановка мини-игры, переключение сцен, сигналы `machine_launched` / `machine_exited`.
- **ScoreStore** — рекорды и последние результаты по каждому автомату, сохранение в `user://scores.cfg`.
- **Settings** — громкость, включение CRT, язык, сохранение в `user://settings.cfg`.
- **Loc** — обёртка над TranslationServer: список из 12 языков, смена локали, хелперы.

### 3.2 Каркас (framework)

- **GameBase** — базовый класс всех мини-игр. Виртуальные методы `_on_start`, `_on_update`, `_on_input`, `_on_draw`. Сигналы `score_changed`, `game_over`, `request_exit`. Все игры наследуются от него.
- **ArcadeScreen** — `SubViewport` 320×240, в который рендерится мини-игра, и `TextureRect` с CRT-шейдером поверх. Размер внутреннего разрешения — единая точка правды.
- **ScoreDisplay** — семисегментный счёт, рисуется процедурно.
- **CRT-шейдер** — barrel distortion, скан-линии, хроматическая аберрация, виньетка.

### 3.3 Хаб (3D)

Зал строится процедурно из примитивов (`hub.gd`): пол, стены, потолок, освещение, пять кабинетов вдоль стен. Каждый кабинет — `cabinet.gd` с корпусом, экраном-заглушкой и зоной взаимодействия. Игрок — `player.gd`, first-person: WASD + мышь, наведение на кабинет, подсказка «E — играть», запуск через `GameManager`.

Хаб — не главное, но делается аккуратно: тёплый свет, ковровая дорожка, афиши на стенах, гул автоматов.

## 4. Единый визуальный стиль

- Внутреннее разрешение мини-игр: **320×240**, растягивается на экран автомата.
- Палитра: ограниченная, 16 цветов, «выцветшая плёнка» — приглушённые тёплые тона.
- Шрифт счёта: семисегментный, крупный.
- CRT поверх всего: скан-линии, лёгкая кривизна, виньетка.
- Звук: короткие синтезированные бипы, без внешних сэмплов (генерируются в `Sfx`).

## 5. Локализация

Проект сразу закладывается под **12 языков**, переводы добавляются в конце.

| Код | Язык |
|---|---|
| `ru` | Русский |
| `en` | English |
| `de` | Deutsch |
| `fr` | Français |
| `es` | Español |
| `it` | Italiano |
| `pt` | Português |
| `pl` | Polski |
| `tr` | Türkçe |
| `zh_CN` | 简体中文 |
| `ja` | 日本語 |
| `ko` | 한국어 |

**Правила с самого начала:**

1. Никакого текста в коде — только ключи (`Loc.t("UI_PLAY")` или `tr("UI_PLAY")`).
2. Все строки — в `localization/strings.csv`, столбец `keys` + 12 языковых столбцов.
3. Шрифты должны покрывать CJK — подобрать шрифт с кириллицей + CJK или переключаемый fallback.
4. Числа и очки — через форматирование, не конкатенацию.
5. Названия автоматов, подсказки, меню, HUD — всё через ключи.

Столбцы языков заполняются по мере готовности; до этого действует fallback на `en`.

## 7. Соглашения по коду

- GDScript, статическая типизация обязательна.
- Один автомат — одна папка `machines/<id>/`, внутри `<id>.gd` (наследник `GameBase`) и `<id>.tscn`.
- Никаких `get_node("../../")` — только `@onready` и экспорты.
- Никаких магических чисел в логике — выносить в константы вверху файла.
- Текст — только ключи локализации.
